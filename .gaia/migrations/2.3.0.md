# Prune overbroad unowned entries after the shell auditor lands

The previous `/update-gaia` has no step that prunes `unowned:` entries. The `code-audit-shell` member this release adds claims `**/*.sh`, so an `unowned:` entry in the project's `.gaia/audit-ci.yml` that reached shell files (for example `scripts/**`) now covers paths a member owns. The roster check fails that as `overbroad-unowned-glob`, and the pre-commit hook would block the update commit.

Do this once, from the update worktree, before `.gaia/VERSION` is written:

1. Read the merged `.gaia/audit-ci.yml`. If it has no member named `code-audit-shell`, there is nothing to do; stop here.
2. Otherwise run the script from the merged tree:

```bash
bash .gaia/scripts/roster-prune-overbroad.sh --root <update worktree root> --member code-audit-shell
```

3. List every `REMOVED` line it prints in the run summary: the glob, the member that now owns it (`code-audit-shell`), and the witness path. If it prints a stderr line saying a removed entry also covered paths no member owns, include that line too and tell the user to add a narrower `unowned:` entry for those paths.
4. If the script exits non-zero, stop the run and relay its stderr line. `.gaia/VERSION` is still at the baseline, so the next run resumes and repeats this note.

The script is idempotent: a second run finds nothing to remove and changes nothing.

# Convert the project's stories to CSF Next

GAIA 2.3.0 moves Storybook stories to CSF Next (CSF4) with test syntax on: a story file imports the preview, builds its stories with `meta.story(...)`, and attaches behavior checks as `.test()` calls. GAIA's readers now refuse an old-format story file and point at the converter, so the project's stories must be converted before the update lands.

## Goal state

Every story file in the project is CSF4 and loads and passes in the Storybook Vitest run, `features.experimentalTestSyntax` is on in `.storybook/main.ts`, and the command below exits 0. The user's story logic is unchanged; only its shape moves.

## Do this

Run once, from the repository root (the update worktree), with stdin closed, after the three-way merge and before `.gaia/VERSION` is written. The command needs network access: it fetches Storybook's CLI at the installed version.

```bash
.gaia/cli/gaia migrate-csf4 --update-merge < /dev/null
```

`--update-merge` tells the command the merge is still uncommitted, so it checks only the paths it writes (the story files, the preview, `.storybook/main.ts` and `package.json`) for uncommitted changes of the user's own. It converts every story file, repairs the preview and main, inlines any story export built by a factory function into a direct `meta.story({...})` call under the same export name (Storybook cannot attach `.test()` to a factory-built export), then typechecks, lints and runs the stories.

Tell the user up front what converting costs: it renames every story test, so the update pull request needs a fresh worthiness verdict for each converted story test before it merges, and any open branch that touches story files has to be finished or rebased onto the update, have the migration re-run on it, and have its worthiness audit re-run, since ledger lines keyed by the old test names stop matching.

## Exit codes

- **0**: converted, or nothing to convert, and verification passed. Continue the update.
- **3**: refused before writing anything. Relay the reason the command printed. For a CSF2 file (`storiesOf` or `Template.bind`), the user converts it with Storybook's `csf-2-to-3` first. For a path with uncommitted changes of the user's own, ask the user how to proceed and never discard their change. Stop the run here; `.gaia/VERSION` is still at the baseline, so the next run resumes and repeats this note.
- **1**: verification failed. The converted files stay in place. Show the user the per-file report (which story files failed to load or failed a test, and the typecheck and lint errors) and the restore command it printed last. Fix the failures with the user, or stop. Never run the restore command without the user's explicit yes.
- **2**: usage error. Check the command spelling above and run it again.

## Idempotent

Following this section again on a migrated tree converts nothing and only verifies, exiting 0 when the stories still load and pass.
