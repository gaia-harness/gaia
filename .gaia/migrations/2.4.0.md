# Bring this machine up to GAIA 2.4.0's toolchain

An update from a release before 2.4.0 runs a skill with no toolchain check, so this note carries it, then owns the hop from below 2.4.0: the move of the app from `frontend/` to `apps/web/` and the walk to the run's target. Check the floors before any file changes.

## Goal state

Every row below passes on this machine. A row that fails stops the update until it passes.

| Tool | Passes at | Platform | Why GAIA needs it |
|---|---|---|---|
| git | git 2.40 or later | all | the light audit review replays the merge with `git merge-tree --merge-base` |
| jq | jq 1.6 or later | all | GAIA's hooks and scripts read JSON with it |
| pnpm | pnpm 12 or later | all | GAIA installs, tests and builds with it |
| lsof | present | macOS | dev-smoke finds the running dev server with it |
| ss | present | Linux | dev-smoke finds the running dev server with it |

The version in a row is only the pass or fail line. A user below it updates to the latest release, never to that version.

## Do this

Run the check from this release's bundle, the folder holding the `.gaia/migrations/` this note was read from, with the working directory at the project root:

```bash
bash <bundle folder>/.gaia/scripts/toolchain-check.sh
```

Exit 0 means every row passes: say nothing and continue. Otherwise bring each short tool up to its latest release in this run. For each `BELOW` or `MISSING` line, show the user the installed version, the floor and the tool's `GUIDE` line, then act on its `ROUTE` line by its class:

- **`run`:** ask once with `AskUserQuestion`, naming the tool, the installed version, the floor and the exact command, with options `Install it (Recommended)` and `Stop`. On `Install it`, run the command.
- **`user`:** the command needs `sudo`, whose password Claude cannot type. Give it to the user as `! <command>`, to type in the prompt so it runs in this session, and wait for them to say it ran.
- **`terminal`:** the command is interactive, such as the Homebrew installer, or changes `PATH` that only a new shell sees, such as `winget`. Never run it. Tell the user to run it in a fresh terminal, then start Claude Code again from that terminal and re-run `/update-gaia`.
- **No `ROUTE` line:** the user updates the tool by its `GUIDE` line or a route below, then says so.

Then run the check again. A pass continues this update. A run install that succeeded while the check still prints `BELOW` means an older copy wins on `PATH`: show `command -v <tool>`.

If the script cannot run, read each version with `git --version`, `jq --version` and `pnpm --version`, and `command -v lsof` or `command -v ss`, judge against the table, and offer the routes below the same way. The routes, each reaching a current release:

- **Update to the latest git or jq on macOS:** `brew install git jq`. Apple's git lags behind Homebrew's.
- **On Debian:** apt stays behind on Debian stable, and backports can too. Install Homebrew on Linux (https://brew.sh), run `brew install git jq`, and put Homebrew's bin folder first on PATH.
- **On Ubuntu:** for git, `sudo add-apt-repository ppa:git-core/ppa`, then `sudo apt-get update`, then `sudo apt-get install -y git`. For jq, apt stays behind too, so use Homebrew on Linux as on Debian.
- **On RHEL and its rebuilds:** dnf stays behind, so use Homebrew on Linux as on Debian.
- **On Fedora:** `sudo dnf upgrade --refresh git jq`. **On Arch:** `sudo pacman -Syu git jq`.
- **On Windows:** `winget install --id Git.Git -e` and `winget install --id jqlang.jq -e`.
- **pnpm:** `corepack disable pnpm` if you use corepack, then `npm install -g pnpm@latest`. pnpm switches itself to the version `package.json` pins.
- **lsof on macOS:** it ships at `/usr/sbin/lsof`, so a missing one means `/usr/sbin` is off `PATH`; Homebrew's lsof is keg-only and cannot fix that. **ss on Linux:** `sudo apt-get install -y iproute2`, or `sudo dnf install -y iproute`.

A row that still fails, or one the user declined: stop, and tell the user to re-run `/update-gaia` once it passes. Nothing has been branched or merged at this point.

## The crossing

### Goal state

- The app lives at `apps/web/`. `.gaia/packages.json` registers it as `web`, its descriptor declares `stack` `web`, and `pnpm-workspace.yaml` lists `apps/*` and `packages/*` beside every entry the user added.
- Every GAIA-shipped file carries the target's content merged with the user's edits, by the ordinary three-way walk against a baseline rekeyed to the new path, so a deleted file stays deleted, a changed file merges and an unmanifested file is untouched. `.gaia/VERSION` reads `<target>` and `.gaia/manifest.json` is the target's.
- The move and the merge land as one commit on an update branch, under the merged hooks, and its pull request is open.

The crossing runs in the main checkout, on the update branch, never in a linked worktree and never in the old skill's Step 4 worktree. Never pass `--no-verify`, never disable a hook, never take GAIA's lockfile, and never open a `.env` file.

### Do this

1. **Preflight.** List linked worktrees with `git worktree list` and ask, with `AskUserQuestion`, to remove each one first. Tell the user that open branches land or rebase onto the update first, that other clones move their ignored env files into `apps/web/` after pulling it, that this session must be a root launch, and that the sweep skips `.env` files, so they check theirs for the old path by hand: Claude never opens one. Then run `git fetch origin`, so the default-branch check reads current refs; a failed fetch (offline, or no `origin` remote) stops here with git's message relayed, never a preflight on stale refs. Then run `"<LATEST_DIR>/.gaia/cli/gaia" update crossing preflight`. `CROSSING_STOP <reason>` stops with its `Next step:` line relayed: nothing has changed. `CROSSING_PASS fresh` or `CROSSING_PASS resume` continues. Record the ignored paths for the sweep with `git ls-files --others --ignored --exclude-standard --directory`.
2. **Branch.** On the default branch, up to date with its remote, cut the update branch in the main checkout: `git switch -c <name>`, the name printed by `bash .gaia/scripts/branch-name-lib.sh name update <LATEST_TAG>`. On the update branch already, stay on it. This branch stands in for the update worktree an after-merge note names, so a note's "update worktree" reads as this checkout.
3. **Move.** Run `"<LATEST_DIR>/.gaia/cli/gaia" update crossing move` and relay every `REPORT` line. Before any install, ask about each newly matched folder whose `package.json` declares lifecycle or gate scripts. Exit 3 stops with its refusal relayed.
4. **Rekey.** Run `"<LATEST_DIR>/.gaia/cli/gaia" update crossing rekey --baseline-tag v<BASELINE>` (the skill's `BASELINE_TAG` when it printed one), adding `--extra-tag <tag>` per extra baseline tag. Use its `BASELINE_DIR` and `EXTRA_DIR` lines for the walk in place of the skill's, and relay each `REKEYED_DECISION` line.
5. **Walk.** Run the ordinary three-way walk to `<target>`, through `.gaia/VERSION` and the manifest write at `<target>`, following the persisted `AFTER_MERGE` lines after its merge. Follow `<LATEST_DIR>/.claude/skills/update-gaia/references/conflict-flow.md` with `RUN_DIR`, a cleared report path, `DECISIONS`, `CHANGELOG_RANGE` (saved by the target bundle's `update-gaia-preflight.sh changelog`), `BASELINE_DIR` set to the rekeyed copy, and the main checkout on the update branch as the acting tree. Snapshot the instructions from L. Run the walk inline in this session, by `merge-execution.md`'s inline fallback: never dispatched. Write `.claude/settings.json` with Edit or Write, so the settings guard's ask reaches the user.
6. **Sweep.** Run `git grep` over tracked files for `frontend/` and the old package name in files the user owns: workspace dependencies, `--filter` arguments, workflow path filters, a `Dockerfile` `--filter` (the kept name, when the user kept one), and `../` in moved config that is not source. Check `.claude/settings.local.json` by hand. Ask on anything unclear. Compare the ignored paths with the list step 1 recorded and confirm each, at its new path, still reads as ignored with `git check-ignore`, since a root-anchored entry stops matching.
7. **Roster.** Run `"<LATEST_DIR>/.gaia/cli/gaia" update crossing roster`, then `bash .gaia/scripts/roster-prune-overbroad.sh --root <main checkout> --member code-audit-frontend`, and report every line of both.
8. **Install.** After the answers from step 3, run `pnpm install`, which renames the importer in the project's own lockfile. It follows the sweep, since a workspace dependency on the old name cannot resolve before it, and precedes the after-merge notes, which need dependencies.
9. **After-merge notes and the skill's tail.** Follow every persisted `AFTER_MERGE` line, the skill's and this note's re-selection, in version order. Then follow the target bundle's skill: Steps 9c, 9c2 and 9d, the `## Quality gate` section, the review point, and Steps 11 and 12, with the settings sync of Step 7e, the ping and the update-check bust those steps carry. The manifest copy keeps its `GAIA_MANIFEST_WRITE=release` spelling. Confirm the permission rules in `apps/web/.claude/settings.json` anchor at `../../` and `bash .gaia/scripts/check-settings-drift.sh` exits 0. When `migrate-csf4` exits 3 with `dirty-write-set` on a renamed config, ask the user to apply the printed repair by hand, then follow that note again: the crossing cannot commit first, and the run stays on its update branch.
10. **One commit.** The review point's commit is the only one, made under the merged hooks: stage named paths, never `--no-verify`, never a hook disabled. An after-merge note treats a rename-only difference from HEAD as clean.
11. **Restart.** This session keeps the old hook registrations until it restarts. After Step 11 opens the pull request, tell the user to restart Claude Code from the repository root before merging it.

An interrupted crossing resumes by following this note again from the update branch. `preflight` prints `CROSSING_PASS resume`, and `move`, `rekey` and `roster` run again regardless, since each finishes only what is still owed. An app the user moved to `apps/web/` by hand takes the same path. The update branch can always be discarded.
