# MSW

[Mock Service Worker](https://mswjs.io/). Intercepts HTTP via Service Worker (browser) or interceptors (Node). One mocking layer for tests, Storybook, and dev.

## Entry points

- Dev: the `msw()` plugin from `msw/vite` in `apps/web/vite.config.ts`, plus `virtual:msw` imported by both `apps/web/app/entry.client.tsx` and `apps/web/app/entry.server.tsx`. With `MSW_ENABLED=true` the dev server mocks browser and SSR requests through that one network. Each entry gates the import on `import.meta.env.DEV`, so production builds drop it. Each entry calls `network.configure({handlers, onUnhandledFrame: 'bypass'})` and then `await network.enable()`. Before that, the server entry runs `resetTestData()` unless the seed surface below is on, since there the gated server owns the baseline.
- `apps/web/test/worker.ts` calls `setupWorker(...)` from `msw/browser` for browser-project tests. It is not the dev server's worker.
- `apps/web/test/test.server.ts` calls `setupServer(...handlers)` from `msw/node` for the Vitest `node` project.

All three share the handler set from `apps/web/test/mocks`. Handler and utility imports come from MSW 3 subpaths (`msw/http`, `msw/utils/<name>`); only `setupWorker` (`msw/browser`) and `setupServer` (`msw/node`) come from their own entry points. The unhandled-request option is `onUnhandledFrame`.

## Seed surface

A dev run holds two `@msw/data` stores: the server network's in the dev server, which answers the API calls loaders and actions make, and the browser network's in the page, one per page load. A Playwright Given builder seeds the server's store, and forwarding makes it the only store a seeded page reads.

- **Gate:** `apps/web/test/msw-seed/plugin.ts`, registered in `apps/web/vite.config.ts`, applies only to `vite serve` with `MSW_SEED=true`, which only the Playwright worker server sets (with `MSW_ENABLED=true`). A build or a plain `pnpm dev` carries none of it.
- **Baseline:** before serving its first request, the gated server runs `resetTestData()` once, so the store holds its baseline whatever a spec does first. A failed reset fails every request and is not retried.
- **Seed:** `POST /__gaia/msw/seed` with `{collection, records}` validates every record against the collection's server schema first, then creates them; a bad record gets a 400 naming the collection, index and field. Builders reach it through `seedRecords` (`apps/web/.playwright/msw-seed.ts`), never a spec directly.
- **Forwarding:** with the gate on, the browser network runs one handler that forwards every request not addressed to the page's own origin to `POST /__gaia/msw/forward`, which answers from the server's handlers and store, so a seeded record reaches client loaders and client fetches; an unhandled request passes through. Forwarding works only once the project's CSP `connect-src` allows its API origin.

## Worker script

`apps/web/public/mockServiceWorker.js` is committed and generated by `msw init`. Regenerate it with `pnpm -C apps/web msw:init`, which runs `msw init` against `msw.workerDirectory` in `apps/web/package.json`. A `node`-project test fails when the committed worker differs from the one the installed msw generates. Storybook loads the same worker from `public/` through `msw-storybook-addon`.

## Companion packages

`@msw/data` (in-memory DB), `apps/web/public/mockServiceWorker.js` (see Worker script). `msw-storybook-addon` is wired into Storybook: a story installs handlers in its `beforeEach` through the addon's CSF Next API. See [[Storybook Stories]] and [[Stories as Tests]].
